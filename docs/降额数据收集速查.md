## 四、常见情况提醒（核对时注意）

1. **不是所有型号都支持两种防护**——IP44 / C5 往往只覆盖部分型号。缺哪个就标"无/不支持"，按我们"无数据留空"铁律处理，别脑补。

2. **IP44 和 C5 是两回事**，别让厂方糊成一个数：
   - IP44 = 防尘防溅的外壳防护（决定机箱开孔/散热 → 影响出力）
   - C5 = 高防腐涂层，针对沿海/腐蚀环境（主要影响外壳工艺 → 通常对出力影响小，很多型号 C5 系数≈1 或接近 1）
   - 要分开要，分开记。

3. **大机座 vs 小机座、低压 vs 中高压**：降额系数常随型号大小变（越大的机子散热折损比例可能不同）。别只抽样 1-2 个型号当全系列用——每个型号都要核对。

4. **样本表格通常给的是"同型号标准版 vs 防护版"的对照额定值**，多在技术参数页的机罩/防腐注释里，找"with enclosure / C5 / IP44 / derating / de-rate"这类字样。

5. **出厂基准**：对照基准请用和各库 cont_h/cont_f（持续功率）同一套口径，免得换算时错位。如果厂方给的是备用功率对照，单独注明。

## 五、拿到数据后（我来做，你不用管）

按已定方案一次性落地：
1. **14 库每型号加 `casing` 子对象**，只写支持的防护：
   ```json
   "casing": {
     "ip44": { "kva_factor": 0.9 },
     "c5":   { "kva_factor": 0.95 }
   }
   ```
2. **前端改逐型号比较**：候选型号装了某防护后可用功率 = 型号标称 × 该系数，拿它 ≥ 用户目标公平比对；没该防护的型号视为不支持。
3. 删掉前端表单那段"全局统一 ÷0.9/÷1"的临时逻辑（commit 3d2823f/69eb2c6 引入的占位）。
