# 电机选型逻辑详解 —— 怎么选、规则是什么

> 面向对象：需要理解/讲解/维护选型算法的销售、售前、开发
> 本文只讲**选型决策逻辑**，不讲代码架构（架构见 `底层逻辑.md`）

---

## 零、一句话说清选型在干什么

> **用户说"我要一台 100kVA 的发电机"，
> 系统要回答"哪台型号、哪个电压档、按哪个功率口径，能在这个海拔和温度下带得动 100kVA"。**

这是个**带修正的容量匹配**问题：
```
型号标称容量 × 修正系数(海拔/温度) ≥ 用户需求
```

三步走：
1. **定口径** —— 用户的 100kVA 到底对应数据库里哪一列？
2. **定折损** —— 现场海拔/温度让机器"缩水"多少？
3. **定匹配** —— 这么多型号里谁"够用且最省"？

---

## 一、第一步：定口径（用户需求 → 数据库字段）

### 1.1 数据库里为什么有 12 个功率列？

因为**同一台机器，在不同工况/温升下，标称容量完全不同**。

三个维度相乘 = 12 列：

| 维度 | 取值 | 含义 |
|---|---|---|
| **温升等级** | H 级 / F 级 | 绕组绝缘允许温升。H 级散热要求低、容量标得高；F 级更保守 |
| **工况** | 持续(cont) / 备用(stdby) | 持续=长期连续运行；备用=应急短时，可多标 10% |
| **备用基准温度** | 40℃ / 27℃ | 备用功率分两个温度基准，27℃ 能标更高 |
| **单位** | kVA / kW | 视在功率 / 有功功率 |

```
cont_h_kVA   H级持续        cont_h_kW
stdby_h_40c_kVA  H级备用40℃  stdby_h_40c_kW
stdby_h_27c_kVA  H级备用27℃  stdby_h_27c_kW
cont_f_kVA   F级持续        cont_f_kW
stdby_f_40c_kVA  F级备用40℃  stdby_f_40c_kW
stdby_f_27c_kVA  F级备用27℃  stdby_f_27c_kW
```

### 1.2 选型取哪一列？（核心规则表）

| 场景 | 主用 PRP（长期运行） | 备用 ESP（应急） |
|---|---|---|
| **低压** | `cont_h`（H 级持续） | `stdby_h_27c`（H 级备用 27℃） |
| **中高压** | `cont_f`（F 级持续） | `stdby_f_27c`（F 级备用 27℃，无则退 `stdby_h_27c`） |

**为什么低压用 H 级、中高压用 F 级？**
- 低压机（400V 级）行业惯例按 H 级标称，H 级是主流交付标准
- 中高压机（3.3kV~13.8kV）大容量机组行业惯例按 F 级标称，更保守可靠

**为什么主用取"持续"、备用取"备用 27℃"？**
- 主用 PRP = Prime Power，机组长期带载，必须按**持续功率**（不会过热）
- 备用 ESP = Emergency Standby，只在停电时短时运行，可以按**备用功率**（更宽松，能标更大）
- 备用取 27℃ 而非 40℃：27℃ 是更宽松的基准，对应 ESP 的应急属性

### 1.3 单位换算（kW ↔ kVA）

```
kVA = kW / PF
kW  = kVA × PF
```

**PF（功率因数）固定取 0.8**（表单已去掉用户选择，用行业标准默认值）。

```js
targetKVA = unit==='kW' ? Math.round(p / 0.8 * 10) / 10 : p;
```

举例：用户说 80kW → `80 / 0.8 = 100 kVA` → 去数据库比 100kVA。

⚠️ **单相是例外**：单相档的 PF 已经在建库时拆档（0.8 和 1.0 是两个不同的 winding_code），
所以单相**不折算**，直接按用户输入的单位比对。

### 1.4 为什么三相统一用 kVA 比？

各型号 PF 有细微差异（多数 0.8，个别不同）。如果直接用 kW 比，
会遇到"标称 kW 大但实际带载能力反而小"的错配。用 kVA（视在功率）作统一口径最公平。

## 二、第二步：定折损（现场条件 → 修正系数）

发电机标称容量是在**标准工况**下测的：**海拔 ≤1000m、环境温度 40℃**。

现场条件更恶劣时，空气稀薄/温度高 → 散热变差 → **必须降额使用**。

```
修正后可用功率 = 标称容量 × 海拔系数(af) × 温度系数(tf)
```

### 2.1 温度修正系数（tf）

**基准：40℃ = 1.0**。低于 40℃ 可增容，高于 40℃ 递减。

**为什么低温能"增容"？** 环境越凉，绕组散热越好，同样温升限值下能带的负载更大。
所以 25℃ 时系数 > 1（如 1.076），这是物理真实，不是错误。

**五套系数表（各品牌用自己手册的数据）：**

| 品牌族 | 基准 | 25℃ | 40℃ | 45℃ | 50℃ | 55℃ | 60℃ |
|---|---|---|---|---|---|---|---|
| 利莱森玛 LSA（H级表） | 40℃ | 1.076 | 1.000 | 0.973 | 0.946 | 0.918 | 0.889 |
| 斯坦福 | 40℃ | 1.000 | 1.000 | 0.970 | 0.940 | 0.910 | 0.880 |
| AGG KI/KK | 40℃ | 1.050 | 1.000 | 0.970 | 0.940 | 0.910 | 0.880 |
| 美奥迪 | 40℃ | 1.070 | 1.000 | 0.960 | 0.930 | 0.910 | 0.890 |
| **中高压** | — | 1 | 1 | 1 | 1 | 1 | 1（**不修正**） |

**几个易错点：**
- **低于最低档取最低档**：25℃ 以下按 25℃ 档（增容），**不是**按 60℃ 末档降额
- **斯坦福 40℃ 及以下 = 1.0**（不增容），40-45℃ 区间按 45℃ 档取值
- **中高压完全不修正**：界面输入海拔/温度不生效，一律按 1000m/40℃ 选型
- **美奥迪档位更密**：一直延伸到 65℃/70℃（0.85/0.82），其它品牌到 60℃ 截止

### 2.2 海拔修正系数（af）

**基准：≤1000m = 1.0**。海拔越高空气越稀薄，散热越差。

| 品牌族 | 1000m | 1500m | 2000m | 2500m | 3000m | 3500m | 4000m | 上限 |
|---|---|---|---|---|---|---|---|---|
| 利莱森玛 LSA | 1.000 | 0.975 | 0.949 | 0.922 | 0.894 | 0.866 | 0.837 | 4000m |
| 斯坦福 | 1.000 | 0.970 | 0.940 | 0.910 | 0.880 | 0.850 | 0.820 | 4000m |
| AGG | 1.000 | 0.970 | 0.940 | 0.910 | 0.880 | 0.850 | 0.820 | 4500m→0.79 |
| 美奥迪 | 1.000 | 0.960 | 0.910 | — | 0.850 | — | 0.780 | 6000m→0.65 |
| **中高压** | 1 | — | — | — | — | — | — | **不修正** |

**超过表末档取末档**（如 LSA 4500m 仍取 0.837）。

### 2.3 ⚠️ AGG / 美奥迪的二维表拆解（最容易搞错的地方）

AGG 和美奥迪的手册给的是 **"海拔 × 温度" 二维交叉表**，不是两个独立表。

**前端怎么处理？拆成两个独立系数相乘：**

```
af（海拔系数）= 表里 "40℃ 这一列"        → 纯海拔影响
tf（温度系数）= 表里 "≤1000m 这一行"      → 纯温度影响
综合修正 = af × tf
```

**验证交叉点能还原：**
```
40℃ / 1000m 交叉点 = af(1000m) × tf(40℃) = 1.00 × 1.00 = 1.00 ✅
（原二维表该单元格正好是 1.00，说明拆解正确）
```

**为什么这么拆？** 二维表直接查需要 (海拔, 温度) 两组输入做二维插值，
拆成两个一维表相乘，代码简单且能容忍用户只填一个参数。

### 2.4 综合修正系数

```js
tot = Math.round(af * tf * 1000) / 1000;   // 保留 3 位小数
```

举例：海拔 2000m + 温度 50℃ + 利莱森玛
```
af = 0.949,  tf = 0.946
tot = 0.949 × 0.946 = 0.897  → 可用功率只剩 89.7%
```

### 2.5 特殊选配修正（IP44 / C5）

**当前临时做法（全局统一系数，待厂家数据到位后替换）：**

```
IP44 防护：降额 10%  → 选型需求 ÷ 0.9（放大需求，等价于可用功率打 9 折）
C5 高防腐：暂不降额  → ÷ 1（数据待补）
无        ：÷ 1
```

**为什么是"÷ 系数"而不是"× 系数"？**
数学等价但实现更简单：
```
可用功率 = 标称 × 0.9  ≥  需求
⟺  标称  ≥  需求 ÷ 0.9
```
把修正做在"需求侧"，这样所有型号共用同一个放大后的目标值 `goal`，比较逻辑不用改。

⚠️ **未来方案**：降额系数本质是**型号属性**（各厂/各型号降额不同），
要下沉到数据库每型号加 `casing` 子对象，前端改"逐型号比较"。

## 三、第三步：定匹配（候选筛选 + 排序）

### 3.1 筛选：哪些型号进入候选池？

**三道过滤，逐条淘汰：**

```
① 频率必须相同         g.frequency === 用户选的频率
② 电压档必须相同       g.winding_code === 用户选的电压档
③ 对应功率列必须有数据  该列不能为空/0，否则淘汰
```

**②的细节**：中高压电压下拉是"组合值"（如 `3300V-W51,3300V-W851`），
一个电压等级可能对应多个绕组，匹配时用"组内任一命中"：
```js
wSet = w.split(',');                    // ['3300V-W51','3300V-W851']
wMatch = wSet.indexOf(g.winding_code) >= 0;
```

**③的意义**：有些型号在某电压档没有该温升等级的数据（如只有 F 级没 H 级），
不能拿空值去比，直接淘汰。这也保证了不会出现 "0 ≥ 需求" 之类的错判。

### 3.2 修正与判定

```js
var r  = 按用途取的标称功率;              // cont_h 或 stdby_h_27c（中高压用 f 版）
var cp = Math.round(r * tot * 10) / 10;  // 修正后可用功率
var ok = cp >= goal;                     // 判定：够用吗？
```

⚠️ **判定用"修正后 vs 放大后目标"，两边都做过处理，才公平。**

### 3.3 排序：谁排第一？

```js
list.sort(function(a,b){
  // ① 中高压先按温升等级：F 级全部排在 H 级前面
  if (isHV) { if (a.grade !== b.grade) return a.grade==='F' ? -1 : 1; }
  // ② 满足需求的排在前面
  if (a.ok !== b.ok) return a.ok ? -1 : 1;
  // ③ 修正后功率与目标值差距最小的排前面
  return Math.abs(a.cp - goal) - Math.abs(b.cp - goal);
});
```

**三级优先级，逐级决胜：**

| 优先级 | 规则 | 业务含义 |
|---|---|---|
| 1（仅中高压） | F 级优先于 H 级 | 中高压惯例优先推荐 F 级（保守可靠） |
| 2 | `ok=true` 优先 | 能带动的排前面 |
| 3 | `\|cp − goal\|` 最小 | **够用且最贴近** —— 不浪费容量 |

**第 3 条是"最优匹配"的精髓**：不是选最大的，而是选"刚好够用"的。
因为发电机选大了浪费钱、油耗高、低载运行效率差（还可能湿堆积）。

### 3.4 最佳匹配 = 排序后第一个 `ok=true` 的型号

```js
for (i…) if (list[i].ok) { top = list[i]; break; }
```

如果没有任何型号 `ok=true` → 显示"无匹配"，建议降低需求或换更大机座/品牌。

## 四、完整实例演算（走一遍真实流程）

### 场景
> 客户：利莱森玛 LSA 低压，50Hz，400V，需要 **备用 100kVA**，
> 安装在 **海拔 2000m**，环境温度 **50℃**，**无特殊选配**

### 步骤 1：定口径

```
品牌 = leroysomer（低压）    → 备用取 stdby_h_27c 列
频率 = 50Hz
电压档 = 6-400（Y-400/Δ-230/YY-200V）
用途 = ESP（备用）
单位 = kVA，功率 = 100
特殊选配 = 无 → optDec = 1
goal = 100 / 1 = 100 kVA
```

### 步骤 2：温度修正

```
品牌 = 利莱森玛 → 用 H 级温度表
t = 50℃ → tf = 0.946
```

### 步骤 3：海拔修正

```
品牌 = 利莱森玛 → ALT_FACTOR
a = 2000m → af = 0.949
tot = 0.949 × 0.946 = 0.897
```

### 步骤 4：筛选候选（同一频率 + 同一电压档 6-400 的全部型号）

以 LSA 44.3 S4 为例：
```
stdby_h_27c_kVA = 100
cp = 100 × 0.897 = 89.7 kVA
ok = 89.7 >= 100 ?  → ❌ 不够
```

**关键洞察**：标称 100kVA 的机器，在 2000m/50℃ 只能出 89.7kVA，
**带不动 100kVA 的负载** —— 这就是为什么必须做修正，光看标称会选错。

### 步骤 5：往上一级找

假设 LSA 46.2 S4 的 `stdby_h_27c_kVA = 115`：
```
cp = 115 × 0.897 = 103.2 kVA
ok = 103.2 >= 100 ?  → ✅ 满足
```

### 步骤 6：排序 + 推荐

在全部 `ok=true` 的型号里，按 `|cp − 100|` 升序：
```
型号 A: cp = 103.2 → 差值 3.2   ← 推荐（够用且最贴近）
型号 B: cp = 118.5 → 差值 18.5
型号 C: cp = 141.0 → 差值 41.0
```

**输出**：
```
🏆 推荐：LSA 46.2 S4
   基准功率(备用27℃)：115 kVA
   修正后功率：115 × 0.897 = 103.2 kVA
   需求功率：100 kVA
   判定：✅ 满足
```

## 五、单相 / 三相怎么分？

### 5.1 判定规则

```js
function isSinglePhase(w, label){
  if (w.startsWith('1ph-')) return true;          // 利莱森玛/斯坦福/美奥迪
  if (/^[A-Z]+\d+-1ph-/.test(w)) return true;     // AGG 特例：D51-1ph-230
  if (/(单相|1ph)/i.test(label)) return true;     // label 兜底
  return false;
}
```

### 5.2 单相 vs 三相的选型差异

| 维度 | 三相 | 单相 |
|---|---|---|
| 功率口径 | 统一 kVA | 按用户输入单位（不折算 PF） |
| 目标值 | `targetKVA = kW/0.8` | 直接用用户输入值 |
| PF | 固定 0.8 | 已拆档（0.8 / 1.0 是不同 code） |
| 出线数 | 6 或 12 | 4（如 LSA 单相） |

**为什么单相不折 PF？** 因为建库时已把 PF 拆成不同的电压档，
每个档的 PF 是确定的，再折算会重复处理。

## 六、中高压与低压的逻辑差异（汇总）

| 维度 | 低压 | 中高压 |
|---|---|---|
| 主用口径 | `cont_h`（H级持续） | `cont_f`（F级持续） |
| 备用口径 | `stdby_h_27c` | `stdby_f_27c`（无则退 `stdby_h_27c`） |
| 海拔/温度修正 | ✅ 按品牌手册 | ❌ **完全不修正** |
| 温升级别判定 | 固定 H 级 | 看实际取到哪一列（F 或回退 H） |
| 电压表述 | V（380V/400V） | kV（3.3kV/10.5kV） |
| 电压下拉 | 平铺或分组 | kV 数值升序 + 组合值（一个电压等级多个绕组） |
| 接线字段 | 有（Y/Δ/YY） | 无（留空） |
| 排序 | ok 优先 → 最贴近 | **F 级优先** → ok 优先 → 最贴近 |

**为什么中高压不修正海拔温度？**
中高压机组多用于大型电站/工业主用，安装环境相对可控（室内/标准机房），
且行业惯例按标准工况标称选型。界面输入不生效。

## 七、规则速查卡（一页纸）

### 取功率列
```
低压 + 主用 → cont_h          低压 + 备用 → stdby_h_27c
中高压 + 主用 → cont_f        中高压 + 备用 → stdby_f_27c（无则 stdby_h_27c）
```

### 修正公式
```
目标值     goal = (单相 ? 用户值 : kW/0.8) ÷ 选配系数
修正系数   tot  = af(海拔) × tf(温度)      // 中高压 tot = 1
可用功率   cp   = 标称功率 × tot
判定       ok   = (cp >= goal)
```

### 选谁
```
第一优先：中高压 F 级 > H 级
第二优先：ok=true
第三优先：|cp − goal| 最小  ← 够用且最贴近
最终推荐：排序后第一个 ok=true 的型号
```

### 基准点
```
标准工况：海拔 ≤1000m，环境温度 40℃   → af=1, tf=1
低于 40℃：系数 > 1（允许增容）
高于 40℃：系数 < 1（必须降额）
```

## 八、常见误判与坑

| 坑 | 说明 |
|---|---|
| **拿标称容量直接比需求** | 必须乘修正系数。2000m/50℃ 下 100kVA 只出 89.7kVA |
| **低温系数当成错误** | 25℃ 系数 1.076 > 1 是物理真实（散热好可增容），不是 bug |
| **低于最低档取末档** | 20℃ 应按 25℃ 档（1.076），不是按 60℃ 档（0.889） |
| **中高压也去修正** | 中高压不修正，界面输入海拔/温度不生效 |
| **单相也折 PF** | 单相 PF 已拆档，再折会重复 |
| **选最大的型号** | 应选"够用且最贴近"，选大了浪费钱、油耗高、低载效率差 |
| **忽略 winding_code 匹配** | 匹配键是 `winding_code`，不是电压数值；接线（conn）纯展示不过滤 |
| **AGG/美奥迪二维表查错** | 要拆成"40℃列"和"≤1000m行"两个一维表相乘 |
