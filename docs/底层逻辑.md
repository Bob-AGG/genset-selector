```
│          │                 │                                 │

        ┌───────────┴───────────┐
        │ leroysomer.json       │ 利莱森玛 LSA 低压
        │ leroysomer-tal.json   │ 利莱森玛 TAL
        │ leroysomer-hv.json    │ 利莱森玛 LSA 中高压
        │ stanford.json         │ 斯坦福 低压
        │ stanford-hv.json      │ 斯坦福 中高压
        │ mecc-alte.json        │ 美奥迪
        │ marathon.json         │ 马拉松 低压
        │ agg-kk.json / agg-ki.json │ AGG
        │ inger-n.json / inger-n3.json │ 英格
        │ qyk.json / qyi.json   │ 铨一
        │ dingol.json           │ 订高
        └───────────────────────┘
```

**关键设计决策：**

| 决策 | 原因 |
|---|---|
| 纯静态、无后端 | 部署在 GitHub Pages，省服务器；数据是标称值不敏感 |
| 单文件 index.html | 无构建链、易于手工维护；改一行即生效 |
| 每品牌独立 json | 各品牌源表结构差异大，独立文件便于单独增补/回滚 |
| 前端算修正、数据只存标称 | 修正系数是"手册规则"非"型号数据"，放前端便于统一调整 |

## 二、数据层：数据库字段模板（24 字段固定）

### 2.1 字段定义（表头顺序不可变，这是死规则）

**基础字段（12）**

| # | 字段 | 含义 | 说明 |
|---|---|---|---|
| 1 | `type` | 固定 `"generator"` | 加载时过滤非此值的记录 |
| 2 | `brand` | 品牌名 | |
| 3 | `model` | 型号 | 产品库按此聚合 |
| 4 | `frequency` | `"50Hz"`/`"60Hz"` | **选型第一过滤键** |
| 5 | `winding_code` | 电压-绕组匹配键 | **选型核心匹配键**，见 2.3 |
| 6 | `winding_label` | 用户可读标签 | 如 `Y-400/Δ-230/YY-200V` |
| 7 | `winding_conn` | 接线方式 | 从 label 提取，如 `Y/Δ/YY`；无则省略 |
| 8 | `voltage` | 电压值 | 从 label 提取，如 `400or230or200V` |
| 9 | `wires` | 出线数 | 6/12 |
| 10 | `pf` | 功率因数 | 三相 0.8；单相 0.8 或 1.0（已拆档） |
| 11 | `exc_std` | 标准励磁 | SHUNT / AREP+ / PMG / self-excited |
| 12 | `exc_opt` | 可选励磁 | 可为空 |

**功率字段（12 = 2 温升等级 × 3 工况 × 2 单位）**

| # | 字段 | 含义 |
|---|---|---|
| 13-14 | `cont_h_kVA` / `cont_h_kW` | **H 级持续**（低压主用口径） |
| 15-16 | `stdby_h_40c_kVA` / `_kW` | H 级备用 40℃ |
| 17-18 | `stdby_h_27c_kVA` / `_kW` | **H 级备用 27℃**（低压备用口径） |
| 19-20 | `cont_f_kVA` / `cont_f_kW` | **F 级持续**（中高压主用口径） |
| 21-22 | `stdby_f_40c_kVA` / `_kW` | F 级备用 40℃ |
| 23-24 | `stdby_f_27c_kVA` / `_kW` | **F 级备用 27℃**（中高压备用口径） |

### 2.2 铁律

1. **表头（字段名+顺序）一个字不能动** — 全品牌统一，前端平铺依赖固定顺序。
2. **无数据留空（省略键），不填 0、不脑补** — 区分"没有数据"与"功率为 0"。
3. **voltage 与 winding_conn 必须数量、顺序一一对应**。
4. **修改前必须备份**（`.bak_时间戳_说明`），随时可回滚。
5. **映射脚本禁用字符串拼接取字段**（`k.split('_',1)` 会把 `cont_h_kVA` 拼成 `cont_h_h_kVA`，必须显式逐字段映射）。

### 2.3 `winding_code` —— 全系统最重要的键

前端三处机制依赖它：

| 机制 | 位置 | 作用 |
|---|---|---|
| 电压下拉生成 | `onParamChange()` | 按 code 去重生成 option |
| 选型过滤 | `doSearch()` | `g.winding_code===w` 精确匹配 |
| 产品库去重 | `renderBrowseDetail()` | `frequency\|winding_code` 联合去重 |

⚠️ **即使某品牌只有一个电压档，也必须给 winding_code**，否则该型号永远选不出来。
各品牌命名**独立、不复用别家**（AGG 的 `B31-*` 只用于 AGG）。

命名规律示例：

| 品牌 | code 样例 | 规律 |
|---|---|---|
| 利莱森玛 | `6-380`, `6-12-440`, `1ph-230`, `8-400` | `绕组号-电压`，`6-12-` 表示 6 号线 12 线出线 |
| 斯坦福低压 | `380V` 系 | |
| AGG | `B31-400`, `T55/T60-600`, `D51-1ph-230` | 官方章节-电压 |
| 英格 | `400V` / `440V` | 品牌自己简明 code |
| 中高压 | `3300V-W51`, `3ph 10.5-11kV 绕组83` | 电压-W绕组号 |

### 2.4 中高压特殊约定

- 电压用 **kV**，`winding_conn` 留空（无接线符号）
- 电压细分档用 **`#`/`&`** 标记（如 6600/6900、10500/11000 独立 code）
- H/F 两条记录**已合并为一条**：原 H 记录功率进 `cont_h/stdby_h_*`，原 F 记录功率进 `cont_f/stdby_f_*`，已去掉 `temp_grade`
- 电压下拉是**组合值**（逗号分隔多 code，如 `'3300V-W51,3300V-W851'`），匹配时用 `split(',')` 后 `indexOf`

## 三、选型主流程（`doSearch()` 逐行剖析）

### 3.0 输入与口径（步骤 1）

```
用户输入：品牌 / 电压(接线) / 频率 / 用途(PRP或ESP) / 功率+单位 / 海拔 / 环境温度 / 特殊选配
```

**目标功率口径换算（关键）**

```js
pfUser  = 0.8;                                    // 功率因数固定 0.8（表单已去掉 PF 选择）
optDec  = optCode==='ip44' ? 0.9 : 1;             // IP44 降额10% → 需求÷0.9 放大
targetKVA = unit==='kW' ? Math.round(p/pfUser*10)/10 : p;   // kW→kVA，保留1位
is1ph   = isSinglePhase(w)                        // 选了单相电压档？
goalUnit= is1ph ? unit : 'kVA';                   // 单相按用户单位比，三相统一 kVA
goalBase= is1ph ? p : targetKVA;
goal    = Math.round(goalBase/optDec*10)/10;      // 含选配放大后的最终目标
```

**逻辑要点：**
- **三相比 kVA**：因为各型号 PF 略有差异，用 kVA 作为统一对比口径最公平。
- **单相不比 kVA**：单相档的 PF 已在数据里拆档（0.8 与 1.0 分成不同 winding_code），再折算会重复，所以直接按用户输入单位比。
- **选配用"÷系数放大需求"而非"乘型号功率"**：等价但实现更简单 —— 装 IP44 后可用功率只有 90%，所以需求要 ÷0.9 才能找到够用的型号。

### 3.1 步骤 2：温度修正（`tf`）

按品牌分派**不同手册的系数表**：

```js
var tf = isHV ? 1
       : isAGG      ? getAggTemp(t)
       : isMecc     ? getMeccTemp(t)
       : isStanford ? getStanfordTemp(t)
       :              getTempFactor(t,'H');   // 默认走 LSA 的 H 级表
```

| 品牌族 | 系数表 | 基准 | 特殊处理 |
|---|---|---|---|
| 利莱森玛 LSA/TAL/其他默认 | `TEMP_FACTOR_H/F/B` | 40℃ = 1.0 | 25℃ 增容 1.076；逐档降额至 60℃ 0.889；**<25℃ 取 25℃ 档**（不接 60℃ 末档） |
| 斯坦福 | `getStanfordTemp()` | ≤40℃ = 1.0 | 40-45℃ 区间按 45℃ 档 (=0.97)；50-55℃ 有笔误修正说明 |
| AGG KI/KK | `AGG_TEMP_FACTOR` | 40℃ = 1.0 | ≤25℃ 增容 **1.05**；45/50/55/60 → 0.97/0.94/0.91/0.88 |
| 美奥迪 | `MECC_TEMP_FACTOR` | 40℃ = 1.0 | ≤25℃ 增容 **1.07**；档位更密（45/50/55/60/65/70 → 0.96/0.93/0.91/0.89/0.85/0.82） |
| **中高压** | 不适用 | 恒为 1 | 界面输入不生效，按默认 40℃ 选型 |

⚠️ **AGG/美奥迪的二维表拆解逻辑**（重要）：
手册给的是"海拔 × 温度"二维表。前端**拆成两个独立系数相乘**：

```
af（海拔系数）= 表里"40℃ 基准列"        → 纯海拔降额
tf（温度系数）= 表里"最低海拔 ≤1000m 行" → 纯温度降额
综合 = af × tf
```
验证：40℃ / ≤1000m 交叉点 → 1.00 × 1.00 = 1.00 ✅（与原表一致）

### 3.2 步骤 3：海拔修正（`af`）

```js
var af = isHV ? 1
       : isAGG      ? getAggAF(a)
       : isMecc     ? getMeccAF(a)
       : isStanford ? getStanfordAF(a)
       :              getAF(a);
```

| 品牌族 | 海拔系数表 | 1000m | 2000m | 3000m | 4000m | 上限 |
|---|---|---|---|---|---|---|
| 利莱森玛 LSA（默认） | `ALT_FACTOR` | 1.0 | 0.949 | 0.894 | 0.837 | 4000m→0.837 |
| 斯坦福 | `ST_ALT_FACTOR` | 1.0 | 0.94 | 0.88 | 0.82 | 4000m→0.82 |
| AGG | `AGG_ALT_FACTOR` | 1.0 | 0.94 | 0.88 | 0.82 | 4500m→0.79 |
| 美奥迪 | `MECC_ALT_FACTOR` | 1.0 | 0.91 | 0.85 | 0.78 | 6000m→0.65 |
| 中高压 | 不适用 | 1 | — | — | — | — |

**综合修正：** `tot = Math.round(af * tf * 1000) / 1000`（保留 3 位小数）

### 3.3 步骤 4-5：候选筛选 + 温升校核

**遍历全部记录，逐条过滤：**

```js
for (每条记录 g) {
  // ① 频率 + 电压档匹配
  if (g.frequency !== freq || !wMatch) continue;      // 中高压 wMatch 用逗号组内查找
  
  var uKey = is1ph ? unit : 'kVA';                    // 读哪个后缀的功率
  
  // ② 主用功率列选择
  var mainCol = (isHV && g['cont_f_'+uKey] > 0) ? 'cont_f' : 'cont_h';
  
  // ③ 备用功率列选择
  var standbyCol = isHV ? (g['stdby_f_27c_'+uKey] > 0 ? 'stdby_f_27c' : 'stdby_h_27c')
                        : 'stdby_h_27c';
  
  // ④ 按用途取基准功率
  var r = duty === 'PRP' ? g[mainCol+'_'+uKey] : g[standbyCol+'_'+uKey];
  if (!r || r <= 0) continue;                         // 无数据 → 淘汰
  
  // ⑤ 修正后可用功率
  var cp = Math.round(r * tot * 10) / 10;
  
  // ⑥ 判定
  list.push({ …, ok: cp >= goal, grade: isHV ? (mainCol==='cont_f'?'F':'H') : 'H' });
}
```

**功率口径选择表（核心）**

| 场景 | 主用 PRP | 备用 ESP |
|---|---|---|
| **低压** | `cont_h`（H 级持续） | `stdby_h_27c`（H 级备用 27℃） |
| **中高压** | `cont_f`（F 级持续） | `stdby_f_27c`（F 级备用 27℃，无则回退 `stdby_h_27c`） |

**中高压的温升级别判定**：不再有 `temp_grade` 字段，而是看"实际取到了哪一列" —— 取到 `cont_f` 就是 F 级，回退到 `cont_h` 就是 H 级。

### 3.4 排序规则

```js
list.sort(function(a,b){
  if (isHV) {                                    // 中高压：先按温升等级
    var ga=(a.grade==='F'?0:1), gb=(b.grade==='F'?0:1);
    if (ga!==gb) return ga-gb;                    // F 级全部排在 H 级前面
  }
  if (a.ok !== b.ok) return a.ok ? -1 : 1;       // 满足需求的排前面
  return Math.abs(a.cp-goal) - Math.abs(b.cp-goal);  // 功率最接近的排前面
});
```

**排序优先级（从高到低）：**
1. （仅中高压）F 级优先于 H 级
2. 满足需求（`ok=true`）优先于不满足
3. 修正后功率与目标的**差值绝对值最小**（即"最优匹配" = 够用且最贴近）

### 3.5 步骤 6：最佳匹配

```js
var top = null;
for (i…) if (list[i].ok) { top = list[i]; break; }   // 排序后第一个 ok 的
var basePw = top ? (duty==='PRP' ? top.ch : top.st) : 0;
```

UI 展示链路：
```
最佳匹配卡片（matchDisplay）  ← 型号 + 温升徽章 + 参数标签 + 「修正后 ≥ 目标 ✅」
     ↓
6 步计算过程（calcDisplay）   ← 可折叠，逐步展示 解析→温度→海拔→温升→备用→判定
     ↓
全部候选表（listDisplay）     ← 平铺全部 24 字段 + 品牌特有字段 + 判定列
```

**候选表列结构：**
```
# | 型号 | 接线/电压 | 出线 | PF | 励磁(标准) | 励磁(可选)
| 持续H_kVA | 持续H_kW | 备用H40_kVA | 备用H40_kW | 备用H27_kVA | 备用H27_kW
| 持续F_kVA | 持续F_kW | 备用F40_kVA | 备用F40_kW | 备用F27_kVA | 备用F27_kW
| [品牌特有字段…] | 判断
```

### 4.3 防御性编码规范（踩坑总结）

```js
// ① esc() 必须类型容错 —— 模板化后字段多为数字
```

### 6.2 降额系数方案（已定，待实施）

**核心认知：降额数据是"型号属性"，不是全局系数** —— 三厂数据各品牌/各型号都不同。

**方案（两步）：**

1. **数据层**：每型号加 `casing` 子对象，只写该型号支持的防护
   ```json
   { "model": "LSA 44.3 S4", "casing": {
       "ip44": { "kva_factor": 0.9 },
       "c5":   { "kva_factor": 0.85 }
   }}
   ```
2. **前端**：改"逐型号比较" —— 候选型号装某防护后可用功率 = 型号标称 × 该系数，拿它 ≥ 用户原始目标公平比对；**装不了的型号视为不支持**（直接淘汰或标注）

**当前临时做法（待替换）**：表单「特殊选配」下拉 = 无 / IP44(÷0.9) / C5(暂 0%)，**全局统一系数**，不准确。

- IP44 的 0.9 **目前是占位值**，也需厂家确认

新增电压档前必须评估，能用段合并/分组的必须合并。

## 八、选型逻辑的根本矛盾（待解决）

**用户心智模型：**
```
品牌 → 频率 → 电压 → 功率 → 海拔 → 温度
```

**实际表单顺序：**
```
品牌 → 电压(接线) → 频率 → 用途 → 功率 → 海拔 → 温度
```

**矛盾点：**
1. **绕组概念对普通用户不可理解** —— 利莱森玛的 `Y-400` / `Δ-230` / `YY-200` 三种接线档让用户懵（其实是同一台机器的三种接法）
2. **接线（winding_conn）用户能理解，应保留**
3. **接线纯展示、不参与过滤** —— 匹配键只有 `winding_code`（代码事实）
4. **电压下拉难度分档：**
   - 🟢 友好：英格 / 中高压 / 斯坦福低压 / 铨一
   - 🟡 偏难：利莱森玛低压 / TAL / 马拉松
   - 🔴 最难：美奥迪 / AGG / 订高（英文 + 接线串 + 多电压段）

**⏳ 4 个待拍板决策点见 `docs/用户操作逻辑.md`（A/B/C/D），用户确认方向后才能动手改。**
