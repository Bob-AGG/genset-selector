## 一、需求与改动范围

### 需求
备用功率原本写死按 27℃ 口径选取。客户希望**能按 40℃ 口径选备用**。
（说明：主用不分温升 —— 主用取的是 H 级/F 级**持续**功率，温升固定；只有备用才分 27/40℃）

### 本次改动（低压 only，中高压暂不做）
| # | 位置 | 改动 |
|---|---|---|
| A | HTML 用途栏 | 新增 `备用 ESP 40℃` 选项（默认隐藏），原选项文字加「27℃」 |
| B | `onParamChange()` 末尾 | 加 `syncDutyOptions(brand)` |
| C | 新增 `syncDutyOptions()` | 中高压隐藏 40℃ 选项并回退选中 |
| D | `doSearch()` duty 解析 | 支持三值 `PRP/ESP/ESP40`，派生 `isESP`、`trKey`、`trLabel` |
| E | `doSearch()` 备用列取值 | `stdby_h_27c` → `stdby_h_<27c\|40c>` 动态 |
| F | `doSearch()` 异常数据排除 | 40℃ 时排除 27℃<40℃ 的反向数据（27 条） |
| G | 步骤5/6 文案 | 「备用27℃」→ 动态「备用27℃/40℃」 |
| H | `basePw` 判断 | `duty==='PRP'` → `!isESP`（等价改写） |
| I | 基准功率标签 | `duty==='ESP'` → `isESP`（等价改写） |

**改动总量：50 行增删（含注释）。**

## 二、第一轮验证：黑盒场景比对

### 方法
搭建 Node 测试脚手架，裁剪出 `index.html` 的 JS 核心（`<script>` 中 `loadBrandData` 之前的部分 + PDF 段），stub 掉 DOM，直接调用 `doSearch()`，抓取屏幕输出。

**关键点**：脚手架需补 `esc`/`escAttr`/`brandLabel` 等被裁掉的函数；Node 内置 `navigator` 是只读 getter，必须用 `Object.defineProperty` 才能赋值。

### 场景集
12 个低压品牌 × 全绕组 × 50/60Hz × `duty(PRP/ESP/ESP40)` × `temp(25/40/50)` × `alt(0/2000)` = **1746 场景**

### 比对项
`calcDisplay`（计算过程）、`matchDisplay`（最佳匹配）、候选表单元格数值

### 结果
```
=== 27℃/主用 路径（1164 场景）===
  统计行数字     : ✅ 0 差异
  最佳匹配型号   : ✅ 0 差异
  计算过程数字   : 582 差异 → 全部为新增文案
  候选表数值     : ✅ 0 差异

归一化新增文案后重新比对：
  计算过程逐字节比对 : ✅ 0 处差异
```

**发现**：所有"差异"都来自我新增的口径标注（`备用模式` → `备用27℃模式`）。
归一化掉这 3 条文案替换规则后，**逐字节 0 差异**。

同时验证 **40℃ 路径正确性**：
```
=== 40℃ 候选表「备用H40_kVA」值核验 ===
  核验行数            : 24300
  值属于该型号合法集合: 24300
  无法匹配的值        : 0 ✅

=== 异常数据(v27<v40) 在 40℃ 候选中出现次数 ===
  出现次数: 0 ✅ 已全部排除
```

⚠️ **踩坑记录**：首次核对报了 147 处"不一致"，排查发现是**核对脚本的锅** —— 斯坦福数据里有 **199 组"同型号+同绕组+同频率"的重复记录**（不同机座/批次），按三元组匹配会取到错的那条。改成**全字段匹配**后 0 不一致。
**教训：斯坦福数据同 key 多记录，任何匹配都必须用全字段。**

### 3.2 白盒：逐行代码真值表验算

不跑场景，直接对 diff 的 50 行做**逻辑等价性证明**。

**关键验算 1 —— duty 解析（块 D）**
```
新代码：
  var duty0 = 选中值
  var duty  = (duty0==='ESP40' && isHV) ? 'ESP' : duty0
  var isESP = duty !== 'PRP'
  var trKey = (duty==='ESP40') ? '40c' : '27c'

真值表：
  duty0='PRP'   → duty='PRP'   → isESP=false → trKey='27c'（不参与备用）
  duty0='ESP'   → duty='ESP'   → isESP=true  → trKey='27c'  ★等价旧逻辑★
  duty0='ESP40' → duty='ESP40' → isESP=true  → trKey='40c'  （新功能）
  duty0='ESP40' 且中高压 → duty='ESP' → trKey='27c'（防御性降级）
```

**关键验算 2 —— 备用列取值（块 E）**
```
旧: standbyCol = 低压 ? 'stdby_h_27c' : (f27c有值 ? 'stdby_f_27c' : 'stdby_h_27c')
新: standbyCol = 低压 ? 'stdby_h_'+trKey : (f+trKey有值 ? 'stdby_f_'+trKey : 'stdby_h_'+trKey)

代入 trKey='27c'：
  低压         → 'stdby_h_27c'    ≡ 旧 ✓
  中高压 f27c有值 → 'stdby_f_27c'    ≡ 旧 ✓
  中高压 f27c无值 → 'stdby_h_27c'    ≡ 旧 ✓
→ 逐字符等价

功率取值真值表：
  旧: r = duty==='PRP' ? main : stdby
  新: r = isESP ? stdby : main
    duty='PRP' → 旧取 main ，新取 main  ✓
    duty='ESP' → 旧取 stdby，新取 stdby ✓
→ 等价
```

**关键验算 3 —— 异常数据排除（块 F）**
```
if(isESP && trKey==='40c' && !isHV){ ... continue; }
  trKey='27c' 时 第二个条件为 false → 短路，永不进入该分支 → 27℃ 零影响 ✓
  主用 duty='PRP' 时 isESP=false → 同样不进入 → 主用零影响 ✓
```

| 块 | 验算 |
|---|---|
| A HTML | `value="ESP"` 未变，仅显示文字加「27℃」 |
| B | 新增一行仅控制显示 |
| C | 新函数，只在切中高压时有行为 |

## 五、最终结论

### 对已有功能的影响
| 功能 | 影响 |
|---|---|
| 主用 PRP 选型 | ✅ **完全无影响**（0 差异） |
| 备用 ESP @27℃ 选型 | ✅ **计算零影响**，仅 2 处口径文案变化 |
| 候选表 / 最佳匹配 / 计算过程 | ✅ 除文案外逐字节一致 |
| PDF 导出（LAST_RESULT） | ✅ 完全无影响 |
| 中高压选型 | ✅ 完全无影响（40℃ 选项不显示） |
| 海拔/温度修正 | ✅ 未触碰（af/tf/tot 与 8 个系数函数逐字节未变） |
| 电压下拉 / 绕组匹配 | ✅ 未触碰 |

### 唯一的行为变化
**27℃ 备用场景下，2 处显示文案变化**：
1. 步骤5 标题右侧：`备用模式` → `备用27℃模式`
2. 步骤5 工作制行：`ESP` → `ESP（备用 27℃）`

这是**有意的改进**（让用户明确当前按哪个温升计算），非缺陷。

### 新增能力
- 低压品牌可选 `备用 ESP 40℃`，按 40℃ 备用功率选型
- 27 条反向异常数据被自动排除（并在帮助页公告说明）
- 中高压不显示该选项（无 40℃ 备用数据）

## 六、数据层面的已知问题（已隔离）

27 条数据出现「27℃ 备用功率 < 40℃ 备用功率」（违反"温度升高功率下降"的物理规律），经用户核对**为厂家手册原文**：

| 品牌 | 数量 | 典型偏差 |
|---|---|---|
| AGG KI（KI 734B/C/D、164A 等 60Hz 机型） | 14 | +20.5%（整齐，疑整行错位） |
| 订高（DG544 系列多电压档） | 8 | +0.1~3.5% |
| 铨一 QYI（314E / 404F） | 3 | +3.5~5.7% |
| 美奥迪（ECP28 VL4 C） | 1 | +2.7% |
| 斯坦福（HCI544E） | 1 | +1.2% |

**处理**：40℃ 选型时**自动排除**这些机型；27℃ 不受影响；帮助页发布公告说明，提示人工复核厂家手册。
**待办**：后续核对源表口径后，再决定是否纳入或改用其他列。
